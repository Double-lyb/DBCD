# 方案 — AI 智能助手「拾墨」

---

## 一、AI 智能助手「拾墨-阅读助手」

### 1.1 命名

> **拾墨-阅读助手**
>
> "拾" — 拾取、发现知识
> "墨" — 书香墨韵、图书馆气质
>
> 定位：图书馆里的智能导览员，帮你找书、答疑、了解借阅状态。

### 1.2 核心问题：API Key 谁来出？

| 方案 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **A：系统统一接入** | 管理员配置一个 API Key，所有用户共用 | 用户零门槛；体验一致；方便管理 | 费用集中；需控制并发 |
| **B：用户自行接入** | 每个用户填入自己的 Key | 费用分散；可选不同模型 | 门槛高，多数读者不会配 |
| **C：混合模式** | 默认系统 Key，也允许用户填入自己的覆盖 | 兼顾两者 | 实现复杂 |

**推荐方案 A（系统统一接入）**，理由：
- 这是**高校图书馆管理系统**，读者是学生和教师，不是开发者
- 让他们去注册大模型平台、获取 API Key、填入系统——这不现实
- 管理员统一配置，一次搞定，所有人受益
- 费用可控：可选用性价比高的国产模型（DeepSeek、Qwen 等），费用极低
- 如果后续需要，可以再加方案 C 作为扩展

### 1.4 知识库设计（固定知识）

存为一个 Markdown 文件 `backend/ai/knowledge_base.md`，作为 System Prompt 的一部分：

```markdown
# 拾墨-阅读助手 知识库

## 系统简介
你叫"拾墨"，是高校图书馆的智能阅读助手。你热情、博学、耐心。

## 借阅规则
- 学生：最多借 10 本，借期 30 天
- 教师：最多借 15 本，借期 60 天
- 超期罚金：0.50 元/天
- 借阅申请有效期：6 小时

## 借书流程
1. 读者在系统中搜索图书 → 提交借阅申请
2. 管理员审批通过 → 读者到图书馆取书
3. 申请 6 小时内未审批自动过期

## 还书流程
读者携带图书到图书馆前台 → 管理员在系统中操作归还 → 如有超期自动计算罚金

## 常见问题
- 如何查自己在借的书？→ 登录后在首页仪表盘即可看到
- 如何申请借书？→ 进入「借书操作」页面，搜索图书点击申请
- 罚金怎么算？→ 超期天数 × 0.50 元/天
...
```

### 1.5 数据注入设计（视图方式开放）

每次对话时，后端自动将当前用户的数据上下文注入 System Prompt：

```
[当前用户信息]
姓名：{reader.name}
学工号：{reader.reader_id}
读者类型：{reader.reader_type}（借阅限额 {max} 本，借期 {days} 天）

[当前借阅]（共 {count} 本）
{for each borrow:}
  - 《{title}》借于 {borrow_date}，应还 {due_date}{if overdue: ⚠超期{overdue_days}天}

[借阅申请]
{for each pending application:}
  - 《{title}》— 申请中（{applied_at}，{expires_at} 前有效）

[超期/罚金]
累计罚金：¥{total_fine}

[馆藏概况]
馆藏总量：{total_books} 本
当前在借：{active_borrows} 本
```

> **注意**：只注入**当前用户有权看到的数据**。读者只看到自己的信息，管理员看到全站概况。

### 1.6 API 配置设计

在 `backend/config.py` 中新增：

```python
# AI 助手配置
AI_ENABLED = True           # 是否启用 AI 助手
AI_API_URL = "https://api.deepseek.com/v1/chat/completions"  # OpenAI 兼容接口
AI_API_KEY = ""             # 管理员填入
AI_MODEL = "deepseek-chat"  # 模型名
AI_MAX_TOKENS = 1000
AI_TEMPERATURE = 0.7
```

支持的主流模型（均为 OpenAI 兼容接口）：

| 模型 | API URL | 特点 |
|------|---------|------|
| DeepSeek-V3 | `api.deepseek.com` | 性价比最高，中文好 |
| Qwen-Max | `dashscope.aliyuncs.com` | 阿里通义千问 |
| GLM-4 | `open.bigmodel.cn` | 智谱清言 |
| GPT-4o | `api.openai.com` | 最强但贵 |

### 1.9 费用估算

以 DeepSeek-V3 为例：
- 输入：¥1 / 百万 tokens
- 输出：¥2 / 百万 tokens
- 每次对话约 1000-2000 tokens（含 system prompt 上下文）
- 每次对话成本约 **¥0.002-0.004**（不到半分钱）
- 如果全校 5000 人每人每天问 10 次：`5000 × 10 × 0.004 = ¥200/天`
- 实际远低于此（不会所有人都高频使用）

### 1.10 安全考虑

| 层级 | 措施 |
|------|------|
| 数据隔离 | 只注入当前用户有权查看的数据 |
| 角色限制 | 不同角色看到的数据范围不同 |
| Prompt 注入防护 | 知识库内容用 `---` 分隔符包裹，与用户输入隔离 |
| 频率限制 | 可选：每人每分钟最多 5 次请求 |
| 敏感信息 | 不将手机号、邮箱等加密字段注入 system prompt |
