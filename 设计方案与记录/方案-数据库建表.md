# 方案-数据库建表

## 目标

完成高校图书借阅管理系统数据库的完整 DDL 设计与创建，包括 8 张表、12 个索引、5 个视图、存储过程/函数、触发器、种子数据。

## 数据库设计

### E-R 图（文字描述）

```
reader_types (1) ──── (N) readers (1) ──── (N) borrow_records (N) ──── (1) books
                             │
                             └────── (0..1) users (1) ──── (N) operation_logs
                             
fine_rules (独立配置表)
backup_records (独立记录表)
```

### 8 张表概览

| 表名 | 主键 | 核心字段 | 关键约束 |
|------|------|---------|---------|
| `reader_types` | reader_type_id (SERIAL) | type_name, max_borrow_count, borrow_days | CHECK(max_borrow_count>0, borrow_days>0) |
| `readers` | reader_id (VARCHAR) | name, reader_type_id(FK), department, phone(BYTEA加密), email(BYTEA加密), password_hash | CHECK(status IN 'active','disabled') |
| `books` | isbn (VARCHAR) | title, author, publisher, total_copies, available_copies, price | CHECK(price>=0, available_copies>=0, available_copies<=total_copies) |
| `borrow_records` | borrow_id (SERIAL) | reader_id(FK), isbn(FK), borrow_date, due_date, return_date, fine_amount, status | CHECK(status IN 'borrowed','returned','overdue'), due_date>=borrow_date |
| `users` | user_id (SERIAL) | username(UNIQUE), password_hash, role, reader_id(FK,UNIQUE) | CHECK(role IN 'admin','librarian','reader') |
| `fine_rules` | rule_id (SERIAL) | fine_per_day, effective_from, effective_to | CHECK(fine_per_day>=0) |
| `operation_logs` | log_id (BIGSERIAL) | user_id(FK), operation_type, table_name, record_id, operation_detail(JSONB) | - |
| `backup_records` | backup_id (SERIAL) | backup_type, file_path, file_size, status, created_by(FK) | CHECK(backup_type IN 'full','differential') |

### 3NF 验证

所有表均满足 3NF：
- **reader_types** 独立提取，避免了 `reader_id → reader_type → max_borrow_count` 的传递依赖
- 其余表均为单列主键，非主属性之间无函数依赖
- `borrow_records.fine_amount` 是快照值（存储归还时计算的罚金），不是实时推导值，不产生传递依赖

## 技术点覆盖

| 要求 | 实现 |
|------|------|
| CHECK 约束 | 6 个：reader_types 正数、readers 状态、books 价格/库存、borrow_records 状态/日期 |
| 视图 | 5 个：v_current_borrowings, v_overdue_books, v_reader_borrowing_stats, v_book_inventory_stats, v_monthly_fine_summary |
| 存储过程 | 1 个：sp_get_reader_borrowings（按读者查当前借阅） |
| 用户函数 | 3 个：fn_calculate_overdue_fine, fn_get_reader_current_borrow_count, fn_can_borrow |
| 触发器 | 5 个：借书减库存+校验、还书加库存+计罚金、自动标记超期、审计日志、删书拦截 |
| 聚合函数 | 5 个全用：COUNT, SUM, AVG, MAX, MIN（分布在各视图中） |
| 安全机制 | 6 项：验证码(应用层) + RBAC(users.role) + 密码bcrypt + pgcrypto加密 + 安全视图 + 安全触发器 |
| 索引 | 12 个：含复合索引 (reader_id, status) 优化核心查询 |

## 执行步骤

1. 在 OpenGauss 中创建 `library_db` 数据库
2. 启用 pgcrypto 扩展
3. 依次执行 6 个 SQL 文件
4. 验证表结构和触发器功能
