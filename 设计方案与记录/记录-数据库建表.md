### 遇到的问题及解决方法

| 问题 | 原因 | 解决 |
|------|------|------|
| `pgcrypto` 扩展不存在 | OpenGauss 5.0 不支持 pgcrypto | 改用 OpenGauss 原生 `gs_encrypt_aes128/gs_decrypt_aes128`，注释说明，加密在应用层实现 |
| `FILTER` 语法报错 | OpenGauss 5.0 基于 PG 9.x，不支持聚合 FILTER 子句 | 改用 `CASE WHEN ... THEN ... END` 等价实现 |
| `CREATE PROCEDURE` 语法报错 | OpenGauss 5.0 不支持 PG 11+ 的 PROCEDURE | 改为 `CREATE FUNCTION ... RETURNS TABLE(...)` |
| `CREATE OR REPLACE TRIGGER` 报错 | OpenGauss 不支持 OR REPLACE 触发器 | 改为 `DROP TRIGGER IF EXISTS ...; CREATE TRIGGER ...` |
| `EXECUTE FUNCTION` 报错 | OpenGauss 使用旧语法 | 改为 `EXECUTE PROCEDURE` |
| `RETURN COALESCE(NEW, OLD)` 报错 | OpenGauss 不支持 COALESCE 用于 ROW 类型 | 改为 `IF TG_OP = 'DELETE' THEN RETURN OLD; ELSE RETURN NEW; END IF;` |
| CHECK 约束 `due_date >= borrow_date` 未触发 | 触发器 `trg_borrow_insert` 自动将 due_date 修正为合法值 | 正常行为，CHECK 作为安全网 |

### 1 个已知特点

- **CHECK `due_date >= borrow_date` 不会在正常借书时触发**：因为 `trg_borrow_insert` 在 CHECK 之前自动计算 `due_date = borrow_date + borrow_days`，保证日期合法。如果直接绕过触发器写入非法数据，CHECK 仍会拦截。
